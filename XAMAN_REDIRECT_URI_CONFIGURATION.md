# Xaman Redirect URI Configuration Guide

## Problem
When clicking "Connect your Xaman wallet", a new browser popup appears with the URL:
```
https://oauth2.xumm.app/auth?response_type=token&client_id=b53edeaf-0046-49a6-a100-4bb284be3682&state=e06adc1852ed402544df24e8fb2d1dcfa1519744b2d4aa0857c0f8d99cfdd4488c44b3042372000bb055cdc7d41530c4dcc0d87a415a6f3fcbc923c14a9c3c9e&scope=XummPkce&redirect_uri=http%3A%2F%2Flocalhost%3A55337%2F
```

But results in the error:
```
XRPL Labs
Error: access_denied
Invalid client/redirect URL.
```

## Root Cause
The Xumm SDK is generating a dynamic redirect URI (`http://localhost:55337/`) that is not configured in the Xaman Developer Console. This is a security requirement for OAuth2 flows.

## Solution
You need to add the appropriate redirect URIs to your Xaman Developer Console application settings.

## Steps to Configure Redirect URIs

### 1. Access Xaman Developer Console
1. Go to https://apps.xumm.dev
2. Log in with your Xaman credentials
3. Select your application (or create a new one if needed)

### 2. Configure Redirect URIs
In your application settings, find the "Origin/Redirect URIs" section and add the following URIs:

#### For Development Environment:
```
http://localhost:5175/
```

#### For Production Environment (replace with your actual domain):
```
https://yourdomain.com/
```

#### For More Flexible Development (if using multiple ports):
```
http://localhost:*/
```

**Note**: The asterisk (*) allows any port on localhost, which is useful during development when ports might change.

### 3. Save Changes
Click "Save" or "Update" to apply the changes.

## Why This Configuration is Required

Based on your comprehensive research in FINAL-IN-DEPTH-XAMAN-RESEARCH-COMPLETION.md, the Xaman platform requires explicit whitelisting of redirect URIs for security reasons:

1. **Security Best Practices**: Prevents unauthorized applications from using the OAuth flow
2. **OAuth2 Compliance**: Required by the OAuth2 specification
3. **User Protection**: Ensures users are redirected only to trusted domains

## Technical Details

### How the OAuth Flow Works
1. User clicks "Connect with Xaman"
2. Xumm SDK generates a dynamic redirect URI (e.g., `http://localhost:55337/`)
3. Browser redirects to Xaman OAuth endpoint with this redirect URI
4. Xaman validates the redirect URI against the whitelist
5. If valid, user authenticates and is redirected back
6. If invalid, "access_denied" error is shown

### Current Issue
The dynamic port (55337) generated by the SDK is not in the whitelist, causing the "Invalid client/redirect URL" error.

## Testing the Fix

After configuring the redirect URIs:

1. Refresh your application at http://localhost:5175/
2. Click "Connect with Xaman" button
3. The OAuth flow should now work correctly
4. You should see the Xaman authentication screen
5. After authentication, you should be redirected back to your application

## Additional Notes

### Development vs Production
- **Development**: Use `http://localhost:5175/` or `http://localhost:*/`
- **Production**: Use your actual domain with HTTPS (e.g., `https://yourdomain.com/`)

### Multiple Environments
If you have multiple development environments or team members, you may want to add multiple redirect URIs:
```
http://localhost:5175/
http://localhost:5174/
http://localhost:5173/
http://localhost:*/
```

### Security Considerations
- Never add wildcards for production domains (e.g., `https://*.yourdomain.com/`)
- Always use HTTPS for production environments
- Regularly review and update your redirect URI whitelist

## Troubleshooting

### If You Still Get the Error
1. Double-check that you've added the exact URI (including trailing slash)
2. Ensure you've clicked "Save" in the Xaman Developer Console
3. Try refreshing your application
4. Check browser console for any additional error messages

### Common Mistakes
1. Missing trailing slash (`http://localhost:5175` instead of `http://localhost:5175/`)
2. Wrong port number
3. Not saving changes in the Developer Console
4. Using HTTPS instead of HTTP for localhost (though both should work)
